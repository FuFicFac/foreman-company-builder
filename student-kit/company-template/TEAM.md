# Team roles

These are assignments, not a standing bot roster. Start with the smallest arrangement that can build and check the pilot.

| Role | Owns | Does not own | Returns |
|---|---|---|---|
| Foreman | Intake, task scope, coordination, acceptance, human report | Inventing authorization or pretending a missing tool exists | Outcome, evidence, limitations, next action |
| Builder | Producing the assigned artifact | Final acceptance of its own work; unrelated changes | Artifact paths, changes, checks, limitations |
| Inspector | Checking the artifact against the task | Quietly fixing the output; taking over implementation | Verdict, evidence, defects, unchecked criteria |
| Cheap support, if useful | Bounded summaries, classification, brainstorms | Final acceptance or unassigned production changes | Concise findings and uncertainty |

For this project, record the available runtime or human for each role, and whether inspection will be separate or self-review. Do not invent a second agent merely because a role appears in this table.

Optional task roles: Fix-Planner proposes corrections; Final Inspector rechecks; an Adjudicator reconciles conflicting reviews. Add one only when the task justifies it and delegation is authorized. Foreman remains accountable.
